# Fill-out spec

One JSON document per video: the timestamped captions as received, optional music beats, and the scenes laid over them. All times are seconds on the video timeline, so values are copied straight from the captions. Emit only the fields listed for the chosen template; omit unused optional fields instead of filling them with null.

## Which template?

Ask what the narration is doing, top to bottom; take the first match.

| The narration… | template / variant |
|---|---|
| opens a video or a chapter | `title` |
| makes one point that should land (optionally one phrase stressed) | `statement` / `keypoint` |
| quotes someone | `statement` / `quote` |
| refers to a picture, screenshot or diagram we have as a file | `media` |
| walks through ordered steps (or a repeating cycle) | `sequence` |
| weighs two or three alternatives | `comparison` |
| gives a default and its exceptions | `rule-exception` |
| picks between modes of one tool | `tool-selection` |
| names one idea and what follows from it | `principle` |
| names the parts of one whole | `framework` |
| groups things into families with members | `categories` |
| lists things, with no further structure: good points, to-dos, or mistakes to avoid | `list` / `cards` · `spotlight` · `bullets` · `checklist` · `warnings` |

## Timing

- **start / end** per scene; the transition to the next scene happens around `end`. A scene lasts at least 2.5 s.
- **at** (optional, on focus and items): when the element appears. Use the timestamp of the caption or word that names it. Without it the scene choreographs itself.
- **highlightAt**, **subtitleAt**: the same idea for a stressed phrase or a subtitle.
- End a scene at least 1.5 s after its last `at`.

## Content

- Labels 1–3 words (≤ 32 chars); list items up to 60. Details 1–3 words (≤ 26).
- Details are optional (0–3). Give a detail only for a point the narration names for that item. Never restate the
  label, never write an instruction to fill the slot ("Weigh against risk"), never invent a point. No details is fine.
- **tone** (optional, on items and focus): how the item reads. `warning` for a risk, a danger, a prohibition, a failure or
  something to avoid; `accent` for the recommended, safe or approved option, or the one the point is about; `muted` for
  something out of scope or not applicable. Leave it out for neutral items. Use it whenever items sit on opposite sides
  (benefit / risk, allowed / not allowed): the slide is coloured by it.
- `statement`: `highlight` must be copied exactly from `text`.
- Icons are optional, all-or-nothing across siblings, from the list below.
- Captions are drawn by the theme in the bottom band; scenes never use it.

## Templates

| template | variants | fields read (plus start, end) |
|---|---|---|
| `title` | text, emblem, editorial | title; optional subtitle, subtitleAt, icon |
| `statement` | keypoint, quote | text; optional highlight, highlightAt, by (quote). No title: the statement is the slide's big text. text is the ONE sentence that should land (at most about 18 words), not the whole narration; never put a section or sub-heading into it (code shows the heading as a small label) |
| `media` | frame, split | image; optional title, subtitle (split), alt, fit (`cover` \| `contain`) |
| `list` | cards, spotlight, bullets, checklist, warnings | title, items 2–8 {label, at, tone, icon}; optional takeaway {label, at, tone}. cards: 2–4 items, each with an icon. spotlight: 2–8 items, each with an icon and at |
| `framework` | canopy, hub | title, focus {label, icon, at}, items 3–6 {label, icon, at} |
| `comparison` | versus, lanes | title, items 2–3 {label, icon, at, tone, details 0–6 as {label, says}} |
| `categories` | constellation, shelves | title, items 2–6 {label, icon, at, tone, details 0–3 (members)} |
| `tool-selection` | switchboard, mode-columns | title, focus {label, icon, at}, items 2–4 {label, icon, at, details 1} |
| `rule-exception` | branch, detour | title, focus {label, icon, at}, items 2–4 {label, icon, at}; first item is the rule |
| `principle` | spotlight, satellites | title, focus {label, icon, at}, items 1–4 {label, icon, at} |
| `sequence` | track, lifecycle | title, items 2–6 {label, icon, at}, in order |

Variants of a template read exactly the same fields.

Rules for this task:
- You receive scenes whose start, end and template are already decided. Keep them exactly; never change a template.
- For each input scene output one scene, in the same order, with start, end, template, a variant allowed for that template, and only the fields the spec lists for that template.
- Take content only from that scene's narration. Do not invent facts or drop the main points.
- Respect the content limits: labels 1-3 words (max 32 characters), list items max 60 characters, details 1-3 words (max 26 characters), title max 56, statement text max 160, and the item counts per template.
- at / subtitleAt / highlightAt: the start time of the narration line that first names that element. It must be inside the scene and at least 1.5 s before the scene's end. Sibling items must not share the same time.
- statement: highlight must be copied exactly from text.
- Icons: give every sibling item an icon from the spec's list, or give none. Title variants emblem and editorial need an icon; without one use variant text.
- Items (and focus): brand: when the item stands for a named product, service or company (as the narration names it), add "brand": its name exactly as the narration says it. Still give the closest icon: the icon is shown until a logo for that brand is supplied. Never tag a generic thing ("an AI model", "a chatbot") as a brand.
- When no listed icon fits an item well, use the closest one and add "wish": the icon you wanted, in 1-2 words (for example "wish": "forklift"). This is logged to grow the icon set.
- title scene: title is the lesson or chapter title as written; a section heading in the same scene goes in subtitle.
- statement scenes have no title (the statement itself is the big text, and the captions repeat it).
- Slide titles (every other scene): a short heading of 2-6 words that names the topic and reads well on its own, like a heading
  in a handbook: a noun phrase ("Information you must never share") or a plain instruction ("Check every delivery"). Never squeeze
  a sentence, a condition or an exception into the title: no colon-joined fragments ("Unless signed: never ship"), no title that
  stops mid-thought. Conditions and exceptions belong in the items or are left to the narration. If the section heading already
  names the topic well, reuse it. When the scene is about one item the narration names (a term, a numbered step, one
  part of something the lesson introduced), the heading carries that name the way the narration gives it.
- The visual must say exactly what the narration says. Never let the layout imply a relationship the narration does not state, and keep conditions and qualifiers (for example "within 30 days", "unless the customer agrees").
- rule-exception: focus is the situation or decision. The first item is the default rule. Every following item must be a case where that default does NOT apply, as the narration says. Never put cases that are examples of the rule itself, or things the narration says are excluded, as exceptions. When the narration says that not every case needs something and then gives examples, needing it is the default rule and those examples are the exceptions; a condition inside an example ("... that does not use X") is part of that example's label, never an exception of its own.
- comparison: the items are the two or three alternatives being weighed against each other (for example plan A versus plan B), with parallel labels; details belong to the item they describe.
- principle: focus is the central idea and appears first: its at is the earliest time in the scene. The items are what follows from it.
- comparison details: give each side one point for every benefit, risk or feature the narration names for it, in the order spoken (up to 6). Do not skip or merge a named one: every benefit, risk or feature the narration names gets its own point.
- comparison details are objects {"label": "Low fees", "says": "the fees are lower"}: "says" copies the exact narration words the point stands for (2-6 words, same language as the narration), so the point lights up when they are spoken. The label stays your short wording.
- details: hard maximum 26 characters each, counting spaces. Shorten the wording yourself (for example "Monthly reports", not "Detailed monthly sales reports"). Details are optional: leave them out rather than invent one.
- tone: on any item, "warning" (risk, prohibition, failure, something to avoid), "accent" (the recommended, safe or approved option, or the key one) or "muted" (out of scope). Leave it out for neutral items. Set it whenever items sit on opposite sides.
- Colour follows meaning, never position: the case that needs approval, is restricted or risky is "warning" even when it
  is the rule or the first item; the safe or allowed case is "accent" even when it is an exception.
- list: the items are parallel, all of one kind (all examples, all things to do, all risks). When the narration lists
  things and then adds a rule or warning about them ("... do not assume it is correct"), list only the things and put the
  rule in "takeaway": {"label": up to 60 characters, "at": when it is said, "tone"}. Never mix the two kinds in the items.
  When the narration first says what something is or what it uses and then gives examples ("Examples are ..."), the
  items are the examples only; what it is goes into the title (a picture can show it).
- list variants, best first (a slide of icons is easier to take in than a slide of text):
  cards      2-4 concrete things an icon can show (a tool, a person, a team, a document, a kind of use, an example),
             each with an icon and its "at" (the card being talked about lights up), labels up to about 32 characters;
  spotlight  3-8 items that each have a fitting icon, including things to do: one item at a time, large, while it is
             spoken, the earlier ones in a strip above. Every item needs an icon and its "at";
  warnings / checklist / bullets   only when the items are abstract and no icon fits them.
- Output only JSON of the form {"scenes": [ ... ]} with no prose and no code fences.
